Lo que pasó, traducido

El arreglo citas vive en la memoria del proceso de Node. Cuando el proceso termina (un reinicio, una actualización, un corte de luz), esa memoria se libera y el arreglo desaparece con todo lo que tenía. Lo viviste en la Clase 2 cada vez que guardabas un archivo y --watch reiniciaba el servidor.

Recuerda

En la Clase 2 separamos Agendia en rutas, controladores y services. ¿Qué capa prometimos que cambiaría cuando llegara la base de datos?

Comprobar

Los services, porque son los únicos que saben dónde se guardan los datos. Hoy lo comprobarás: las rutas no cambian, los services cambian por dentro y los controladores solo aprenden a esperar la respuesta de la base (una palabra: await).

Del arreglo a la tabla

Cada tabla representa un tipo de cosa; las llaves conectan sus filas sin duplicar datos.

En la Clase 2 viste que una base de datos relacional guarda la información en tablas: cada tabla es un tipo de cosa, cada fila un registro y cada columna un campo con un tipo fijo. También creaste la base agendia, vacía. Hoy decidimos qué tablas lleva y cómo se conectan.

3.2 · Las llaves

Definición técnica

Llave primaria y llave foránea

La es la columna que identifica cada fila sin repetirse: el id. La es una columna de una tabla que guarda la llave primaria de otra; la base de datos garantiza que siempre apunte a una fila que existe. En Cita, la columna servicioId es una llave foránea hacia Servicio.

En la vida real

Es el número de la historia clínica en la ficha de una cita médica: la ficha no copia toda la historia, solo el número. Si alguien cambia un dato de la historia, todas las fichas lo ven al buscarla. Y nadie puede anotar en la ficha un número de historia que no existe.

Relación 1 a N

Un servicio puede tener muchas citas (el corte de raza se agenda veinte veces por semana), pero cada cita es de un solo servicio. Esa forma se llama relación uno a muchos (1 a N), y siempre se resuelve igual: la llave foránea va en el lado de "muchos", es decir, en Cita.

Para pensar

Si cada cita guardara una copia completa del servicio (nombre, duración y precio), ¿qué pasaría el día que Valentina sube el precio del corte de raza?

Comprobar

Las citas viejas quedarían con el precio anterior y las nuevas con el nuevo, y nadie sabría cuál es el oficial. Con la llave foránea, el precio vive en un solo lugar (la fila del servicio) y todas las citas lo leen de ahí.

3.3 · Un traductor para SQL

Para crear estas tablas, PostgreSQL entiende SQL (CREATE TABLE …). Podríamos escribirlo a mano, pero hoy usamos un : una herramienta que traduce entre los objetos de JavaScript y las filas de las tablas. Tú describes las tablas en un archivo, el ORM escribe el SQL y te da funciones como prisma.cita.create(...) para guardar sin escribir INSERT. El ORM de hoy es Prisma.

Definición técnica

ORM

Un ORM (Object-Relational Mapping, mapeo objeto-relacional) es una librería que relaciona las clases u objetos de un lenguaje con las tablas de una base relacional: genera las consultas SQL a partir de llamadas a funciones y convierte las filas que responde la base en objetos del lenguaje.

En la vida real

Es un traductor en una reunión: tú hablas en JavaScript ("crea esta cita"), el traductor se lo dice a PostgreSQL en SQL (INSERT INTO "Cita" …) y te devuelve la respuesta en JavaScript (un objeto con id).

Construir · async/await

El catálogo sale de la base

El service consulta PostgreSQL y el controlador espera la promesa antes de responder.

Un arreglo responde al instante. Una base de datos es otro programa: la consulta viaja, PostgreSQL la resuelve y la respuesta vuelve. Por eso Prisma devuelve una . Para usar el dato hay que esperar con await.

Definición técnica

Promesa

Una Promise representa un resultado que todavía no existe: puede quedar cumplida con un valor o rechazada con un error. await detiene la función donde está escrito hasta que la promesa se resuelve; solo se usa dentro de una función async o en el nivel superior de un módulo.

En la vida real

Es el turno de la panadería: no es el pan, es la garantía de que te lo van a entregar. await es esperar a que digan tu número antes de irte con el pan.

Construir · errores

El service decide; el middleware responde

Un único formato JSON atiende 400, 404 y 409 sin repetir condiciones en los controladores.

/api/servicios/abc produce una página HTML de error 500 con rutas internas. El cliente se equivocó: debería recibir 400, en JSON y sin detalles del servidor. Además, el mismo if de 404 estaba repetido entre servicios y citas.

Definición técnica

Middleware de errores

En Express es una función con cuatro parámetros (err, req, res, next), registrada con app.use después de las rutas. Express la ejecuta cuando una pieza anterior produce un error.

En la vida real

Es la oficina de atención al cliente de un almacén: cuando algo falla en cualquier sección, todos mandan el caso a la misma oficina, que contesta siempre con el mismo formato y sin mostrar la bodega.

export function leerId(valor, recurso) {
  const id = Number(valor);
  if (!Number.isInteger(id) || id <= 0) {
    throw new ErrorHttp(400, `El id de ${recurso} debe ser un número entero positivo (llegó "${valor}")`);
  }
  return id;
}

export function exigirTexto(datos, campo) {
  if (typeof datos[campo] !== 'string' || datos[campo].trim() === '') {
    throw new ErrorHttp(400, `El campo ${campo} es obligatorio y debe ser un texto`);
  }
}

export function manejarErrores(err, req, res, next) {
  if (err instanceof ErrorHttp) {

const ESTADOS = ['PENDIENTE', 'CONFIRMADA', 'CANCELADA', 'COMPLETADA'];

function validarCita(datos) {
  exigirTexto(datos, 'clienteNombre');
  exigirTexto(datos, 'clienteTelefono');
  exigirTexto(datos, 'profesional');
  if (typeof datos.fechaHora !== 'string' || Number.isNaN(Date.parse(datos.fechaHora))) {
    throw new ErrorHttp(400, 'fechaHora debe ser una fecha válida, por ejemplo "2026-11-07T15:00:00-05:00"');
  }
}

const MINUTO_MS = 60 * 1000;

function terminaEn(inicio, duracionMin) {
  return new Date(inicio.getTime() + duracionMin * MINUTO_MS);
}

async function verificarAgendaLibre(profesional, inicio, duracionMin) {
  const fin = terminaEn(inicio, duracionMin);
  const citas = await prisma.cita.findMany({
    where: { profesional, estado: { not: 'CANCELADA' } },
    include: { servicio: true },
  });
  const cruce = citas.find((cita) =>
    cita.fechaHora < fin && inicio < terminaEn(cita.fechaHora, cita.servicio.duracionMin));
  if (cruce) {
    throw new ErrorHttp(409, `${profesional} ya tiene la cita ${cruce.id} en ese horario`);
  }
}

export async function crear(datos = {}) {
  validarCita(datos);
  const servicio = await serviciosService.buscarPorId(datos.servicioId);
  const fechaHora = new Date(datos.fechaHora);
  await verificarAgendaLibre(datos.profesional, fechaHora, servicio.duracionMin);

  return prisma.cita.create({
    data: {
      servicioId: servicio.id,
      clienteNombre: datos.clienteNombre,
      clienteTelefono: datos.clienteTelefono,
      profesional: datos.profesional,
      fechaHora,
      notas: datos.notas,
    },
  });
}

import prisma from '../lib/prisma.js';
import { ErrorHttp } from '../lib/error-http.js';
import { leerId, exigirTexto } from '../lib/validaciones.js';

function validarServicio(datos) {
  exigirTexto(datos, 'nombre');
  if (!Number.isInteger(datos.duracionMin) || datos.duracionMin <= 0) {
    throw new ErrorHttp(400, 'duracionMin debe ser un número entero mayor que 0');
  }
  if (!Number.isInteger(datos.precio) || datos.precio < 0) {
    throw new ErrorHttp(400, 'precio debe ser un número entero de 0 o más');
  }
}

export function listar() {
  return prisma.servicio.findMany({ orderBy: { id: 'asc' } });
}

export async function buscarPorId(valorId) {
  const id = leerId(valorId, 'servicio');
  const servicio = await prisma.servicio.findUnique({ where: { id } });
  if (!servicio) throw new ErrorHttp(404, `No existe el servicio con id ${id}`);
  return servicio;
}

export function crear(datos = {}) {
  validarServicio(datos);
  return prisma.servicio.create({
    data: { nombre: datos.nombre, descripcion: datos.descripcion, duracionMin: datos.duracionMin, precio: datos.precio },

}

export async function actualizar(valorId, datos = {}) {
  const servicio = await buscarPorId(valorId);
  validarServicio(datos);
  return prisma.servicio.update({
    where: { id: servicio.id },
    data: { nombre: datos.nombre, descripcion: datos.descripcion, duracionMin: datos.duracionMin, precio: datos.precio },
  });
}

export async function eliminar(valorId) {
  const servicio = await buscarPorId(valorId);
  const citas = await prisma.cita.count({ where: { servicioId: servicio.id } });
  if (citas > 0) {
    throw new ErrorHttp(409, `No se puede eliminar "${servicio.nombre}": tiene ${citas} cita(s) registradas`);
  }
  await prisma.servicio.delete({ where: { id: servicio.id } });
}

Agendia ya no pierde citas

Valentina perdió la agenda de un sábado porque las citas vivían en la memoria del servidor, y Agendia dejó cruzar dos perros con Dana. Hoy las citas y el catálogo viven en PostgreSQL y sobreviven a cualquier reinicio; la API rechaza los datos incompletos con 400, avisa con 404 lo que no existe y responde 409 cuando un groomer ya está ocupado.

  1. Modelado relacional: una tabla por tipo de cosa, una llave primaria por fila y una llave foránea en el lado "muchos".
  2. ORM con Prisma: el schema describe, la migración crea y el cliente consulta. Como cada consulta tarda, se espera con await.
  3. Errores centralizados: el service lanza un ErrorHttp; un solo middleware lo responde.
