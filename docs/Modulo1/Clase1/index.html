Comprender

Backend y Node.js

3.1 · Dos partes de una misma aplicación

Toda aplicación web tiene dos partes. El frontend es lo que el usuario ve y toca: la página, los botones, los formularios. El backend es lo que no se ve: el programa que guarda los datos, aplica las reglas y responde.

Backend · definición técnica

Un backend es un programa que corre en un servidor, recibe peticiones a través de la red, aplica las reglas del negocio, consulta o guarda datos y devuelve una respuesta.

3.2 · Backend · en la vida real

Piensa en un restaurante. El salón, la carta y los meseros son el frontend. La cocina es el backend: nadie la ve, pero ahí se decide qué se puede preparar, con qué ingredientes y a qué precio. El mesero lleva el pedido a la cocina y trae el plato: ese ir y venir es la comunicación por la red.

Backend · en Agendia

En Huellitas, el backend es el único lugar donde vive la agenda y el precio oficial de cada servicio. La recepcionista, Valentina y los clientes le preguntan a él, y todos reciben la misma respuesta.

3.3 · La conversación: petición y respuesta

El frontend y el backend se comunican con el protocolo . Siempre es una conversación de dos pasos: alguien hace una petición y el servidor devuelve una respuesta.

3.4 · Node.js · definición técnica

Node.js es un entorno de ejecución de JavaScript que corre fuera del navegador. Usa el motor V8 de Google Chrome para ejecutar el código y le agrega lo que un navegador no permite: escuchar conexiones de red, leer y escribir archivos y comunicarse con el sistema operativo.

Node.js · en la vida real

JavaScript es el idioma; el navegador y Node.js son dos lugares de trabajo distintos. En el navegador, JavaScript atiende el salón (botones, pantallas). En Node.js, el mismo idioma trabaja en la cocina (red, archivos, datos). No aprendes otro lenguaje: cambias de lugar de trabajo.

3.5 · Por qué Node.js en un programa AI Fullstack

Con Node.js usas un solo lenguaje en todo el producto: el backend de este módulo y el frontend en React del Módulo 2. Además, los SDK de las APIs de inteligencia artificial que usaremos en la Clase 4 tienen versión oficial para JavaScript.

Para pensar

Si un cliente de Huellitas abre Agendia en su celular, ¿en qué computador corre el código del navegador y en cuál corre el código de Node.js?

Comprobar
El código del navegador corre en el celular del cliente. El código de Node.js corre en el servidor de Agendia, que puede estar en otra ciudad. Por eso el backend es el lugar seguro para los precios oficiales: el cliente no lo puede modificar.

2

Decidir qué responder a cada petición

Aquí está el corazón del servidor: una función que se ejecuta cada vez que llega una petición y decide la respuesta.

Líneas 11–20
const servidor = http.createServer((req, res) => {
  if (req.method === 'GET' && req.url === '/api/servicios') {
    res.writeHead(200, { 'Content-Type': 'application/json; charset=utf-8' });
    res.end(JSON.stringify(servicios));
    return;
  }

  res.writeHead(404, { 'Content-Type': 'application/json; charset=utf-8' });
  res.end(JSON.stringify({ error: 'Ruta no encontrada' }));
});
  1. L11http.createServer((req, res) => {

    🟩 Node.js createServer · ⬜ Convención los nombres req y res · createServer construye el servidor y recibe una función flecha que Node ejecutará cada vez que llegue una petición. Node le entrega dos objetos: req (request, la petición que llegó) y res (response, la respuesta que vamos a armar).

  2. L12if (req.method === 'GET' && req.url === '/api/servicios')

    🟨 JavaScript if, === y && · 🟩 Node.js req.method y req.url · if pregunta una condición. req.method es el método HTTP y req.url es la ruta pedida. === compara que sean exactamente iguales y && exige que se cumplan las dos a la vez.

  3. L13res.writeHead(200, { 'Content-Type': … })

    🟩 Node.js writeHead · el encabezado Content-Type lo define el estándar HTTP · writeHead escribe la primera parte de la respuesta: el código 200 (todo bien) y los encabezados. Content-Type: application/json avisa que el cuerpo es JSON, y charset=utf-8 permite que "Baño" llegue con su eñe.

  4. L14res.end(JSON.stringify(servicios))

    🟨 JavaScript JSON.stringify · 🟩 Node.js res.end · JSON.stringify convierte el arreglo de JavaScript en texto JSON, porque por la red solo viaja texto. res.end envía ese texto y da la respuesta por terminada.

  5. L15return;

    🟨 JavaScript · Sale de la función para que no se ejecute el código de abajo. Sin él, intentaríamos responder dos veces y Node lanzaría un error.

  6. L18–19la respuesta `404

    🟩 Node.js · 🟪 Decisión del proyecto el mensaje · Si la petición no coincidió con nada, respondemos 404 (no encontrado) con un JSON que explica el error. Así quien pregunta por una ruta inexistente recibe una respuesta clara y no un silencio.

import http from 'node:http';

const PUERTO = 3000;

const servicios = [
  { id: 1, nombre: 'Baño completo', duracionMin: 60, precio: 45000 },
  { id: 2, nombre: 'Corte de raza', duracionMin: 90, precio: 65000 },
  { id: 3, nombre: 'Spa relajante', duracionMin: 120, precio: 85000 },
];

const servidor = http.createServer((req, res) => {
  if (req.method === 'GET' && req.url === '/api/servicios') {
    res.writeHead(200, { 'Content-Type': 'application/json; charset=utf-8' });
    res.end(JSON.stringify(servicios));
    return;
  }

  res.writeHead(404, { 'Content-Type': 'application/json; charset=utf-8' });
  res.end(JSON.stringify({ error: 'Ruta no encontrada' }));
});

servidor.listen(PUERTO, () => {
  console.log(`Servidor HTTP escuchando en http://localhost:${PUERTO}`);

Cómo leer el error

Se lee de abajo hacia arriba. SyntaxError dice que Node no entiende la sintaxis. "Cannot use import statement outside a module" dice cuál: usaste import, pero Node está leyendo el archivo con otro sistema. Y la advertencia de arriba te dice exactamente cómo arreglarlo.

Para pensar

El error dice que no puedes usar import "fuera de un módulo". Mira la última línea del package.json. ¿Qué crees que hay que cambiar?

Comprobar
La línea "type": "commonjs". Con ese valor, Node lee los archivos con el sistema antiguo (CommonJS, que usa require). Si la cambias a "type": "module", Node usa los módulos estándar de JavaScript, los mismos que usarás en React.

7.1 · El problema que acabas de ver

Con Node.js puro, cada ruta nueva es otro if que compara texto, y cada respuesta exige escribir encabezados y convertir a JSON a mano. Agendia tendrá decenas de rutas: servicios, citas, clientes, negocios. Hace falta algo que organice ese trabajo.

Framework · definición técnica

Un es un conjunto de código ya escrito que define cómo se organiza tu aplicación: tú escribes las partes propias del negocio y el framework se encarga del trabajo repetitivo y de llamar tu código en el momento correcto.

7.2 · Express · definición técnica

Express es un framework minimalista para construir servidores web y APIs en Node.js. Por dentro usa el mismo módulo http que acabas de usar, y encima te da un sistema de rutas: asocias un método y una ruta con la función que la atiende.

Express · en la vida real

Volvamos a Huellitas. Con Node puro, la recepcionista lee cada mensaje de WhatsApp de principio a fin para saber qué quiere el cliente. Con Express, el negocio tiene un conmutador: "para precios marque 1, para agendar marque 2". Cada llamada llega directo a la persona encargada.

7.3 · Ruta (endpoint)

Una ruta o endpoint es la combinación de un método HTTP y una dirección, por ejemplo GET /api/servicios, junto con la función que la atiende. Cada endpoint es una de las "opciones del conmutador" de Agendia.

10.2 · Parámetro de ruta · definición técnica

Un parámetro de ruta es un segmento variable de la URL, que en Express se declara con dos puntos (:id). Express toma el valor que llegó en esa posición y lo guarda en req.params.

10.3 · Parámetro de ruta · en la vida real

Es como el número de turno en un banco. La ventanilla es siempre la misma ("atención de servicios"), pero cada persona llega con un número distinto, y el cajero busca según ese número.

Sin IA aquí

Antes de ver el código, piensa tú los tres pasos que debe hacer la ruta: qué recibe, cómo busca y qué responde si no encuentra. Ese razonamiento es lo que la clase está entrenando.

Para pensar

La ruta recibe el id que llega en la URL y debe buscar el servicio en el arreglo. ¿Qué debe responder si alguien pide el servicio 9, que no existe en Huellitas?

Comprobar

11.1 · Por qué ahora

Agendia ya funciona. Si mañana dañas algo, necesitas poder volver a este punto. Y tu equipo (y tus futuros empleadores) necesitan ver tu código. Para eso existen Git y GitHub.

11.2 · Git y GitHub

Git es el programa que guarda en tu computador la historia de cambios del proyecto. Cada punto guardado se llama . GitHub es el sitio web donde publicas esa historia para compartirla y respaldarla. En la vida real: Git es el álbum de fotos de tu proyecto; GitHub es la nube donde lo respaldas y lo muestras.

13.1 · Lo que resolvimos

Valentina tenía un problema de "fuente de verdad": cada quien con su cuaderno y su precio. Hoy Agendia tiene un servidor que responde el catálogo oficial de Huellitas, igual para todos, y el código está respaldado en GitHub.

13.2 · Las tres ideas que se quedan

  1. Un backend es el único lugar donde viven los datos y las reglas, y responde a cualquiera que le pregunte por HTTP. Node.js permite escribirlo en JavaScript.
  2. Express organiza el servidor en rutas: un método, una dirección y una función que responde.
  3. AI-first es un hábito: piensas tú, la IA revisa o explica, y validas tú.
